Tutoriais / Trilha 04

HTML + CSS + JavaScript

Projeto: lista de estudos

Uma sequência didática para integrar estrutura, estilo e comportamento em um produto funcional.

2–3 aulasProjeto em duplaAvaliação formativa

Produto esperado

Uma aplicação que adiciona, filtra, conclui e remove tarefas de estudo, salva os dados no navegador e funciona em celular e desktop.

Níveis de Bloom1. Lembrar2. Compreender3. Aplicar4. Analisar5. Avaliar6. Criar
1Lembrar

Recupere os conhecimentos prévios

Mapa do projeto

  • HTML: formulário, input, button, ul e template.
  • CSS: classes, Box Model, Flexbox, estados e media query.
  • JavaScript: querySelector, eventos, arrays, map, filter e localStorage.

Diagnóstico de 5 minutos

Peça que cada dupla desenhe três colunas — estrutura, aparência e comportamento — e distribua os conceitos acima.

2Compreender

Explique o fluxo de dados

Modelo mental

Evento → atualizar dados → salvar → renderizar. O array de tarefas é a fonte de verdade. A interface apenas representa seu estado atual.

Usuário envia formulário
  → validar texto
  → adicionar objeto ao array
  → salvar no localStorage
  → redesenhar a lista

Explique o risco

Por que editar somente o HTML visível causa problemas? Porque o array e o armazenamento deixam de representar a tela.

3Aplicar

Construa a versão mínima

1. Estrutura HTML

<main>
  <h1>Meu plano de estudos</h1>
  <form id="form-tarefa">
    <label for="tarefa">Nova tarefa</label>
    <input id="tarefa" required>
    <button>Adicionar</button>
  </form>
  <ul id="lista-tarefas"></ul>
</main>

2. Comportamento inicial

const form = document.querySelector("#form-tarefa");
const campo = document.querySelector("#tarefa");
const lista = document.querySelector("#lista-tarefas");
let tarefas = [];

form.addEventListener("submit", evento => {
  evento.preventDefault();
  tarefas.push({
    id: crypto.randomUUID(),
    texto: campo.value.trim(),
    concluida: false
  });
  campo.value = "";
  renderizar();
});

Incremento

Implemente renderizar() usando map() ou criação de elementos. Depois, adicione CSS para organizar formulário e lista.

4Analisar

Divida responsabilidades

Arquitetura sugerida

FunçãoResponsabilidade
adicionarTarefa()Validar e alterar o array
alternarTarefa(id)Atualizar o estado concluída
removerTarefa(id)Filtrar o item pelo id
salvarTarefas()Persistir em JSON
renderizar()Sincronizar DOM com dados

Diagrama de dependências

Identifique quais funções alteram dados, quais alteram interface e em quais pontos salvarTarefas() deve ser chamada.

5Avaliar

Teste e revise o produto

Roteiro de testes

  • Impede tarefa vazia ou composta só por espaços.
  • Adiciona duas tarefas sem perder a primeira.
  • Conclui e reabre uma tarefa.
  • Remove apenas a tarefa selecionada.
  • Mantém dados depois de recarregar.
  • Permite uso por teclado e em tela pequena.

Teste cruzado

Cada dupla testa a aplicação de outra. Registre passos, resultado esperado, resultado encontrado e gravidade do problema.

Regra de feedback: descreva o comportamento observado e seu impacto antes de sugerir uma correção.

6Criar

Personalize e apresente

Produto autoral

Escolha pelo menos duas extensões e redesenhe a identidade visual:

  • Filtros: todas, pendentes e concluídas.
  • Prioridade ou categoria de estudo.
  • Contador e barra de progresso.
  • Edição do texto da tarefa.
  • Data limite e ordenação.
  • Tema claro/escuro.

Apresentação final — 5 minutos

  1. Demonstre o fluxo principal.
  2. Explique uma decisão de HTML, uma de CSS e uma de JavaScript.
  3. Mostre um problema encontrado e como foi resolvido.
  4. Indique a próxima melhoria.
